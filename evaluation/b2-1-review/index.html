B2-1 · CODE REVIEW GUIDE

B2-1 평가 · 복습

이 미션은 데이터를 파일에 영구 저장하고 추가·조회·수정·삭제(CRUD), 검색·요약·입출력을 구현하며, 프로그램의 입력부터 결과 출력까지 이어지는 흐름을 익히는 과제입니다. 모델·저장소·서비스·CLI의 책임을 나누고, yield 기반 스트리밍·데코레이터·타입 힌트를 사용한 이유를 실제 코드로 스스로 설명하는 것이 목표입니다.

01 · FILES & ROLES

프로젝트 전체 구조

폴더는 자료를 묶고, .py 파일은 각자 한 가지 역할에 집중합니다.

실제 주요 파일

  • B2-1/
    • budget_app/실행 코드
      • __main__.py시작점
      • cli.py명령·입출력
      • services.py업무 처리
      • validators.py값 검사
      • models.py데이터 모양
      • repositories.py파일 읽기·쓰기
      • decorators.py공통 오류 처리
      • __init__.py패키지 표시
    • data/실행 후에도 남는 값
      • transactions.jsonl
      • categories.jsonl
      • budgets.jsonl
    • evaluation/평가·실습 자료와 이 페이지
    • source/미션 원본
    • README.md사용 방법

초보자를 위한 역할 구분

접수 창구 cli.py
명령을 알아듣고 필요한 값을 받으며 결과를 보여줍니다.
작업 담당 services.py
거래를 추가할지, 무엇을 계산하고 저장할지 결정합니다.
규칙 확인 validators.py
날짜·금액 같은 값이 허용되는지 검사합니다.
양식 models.py
거래·예산·월별 결과가 어떤 값으로 이루어지는지 정의합니다.
보관 담당 repositories.py
파일을 열고 거래·카테고리·예산을 읽거나 씁니다.
공통 안내 decorators.py
처리 대상 오류를 사람이 읽기 쉬운 메시지로 바꿉니다.

02 · FROM INPUT TO RESULT

프로그램 전체 흐름

add 명령을 예로 들어 입력이 저장되고 결과가 돌아오는 길을 따라갑니다.

01

실행과 입력

python3 -m budget_app은 __main__.py를 시작합니다. cli.py는 명령과 옵션을 읽고 필요하면 값을 질문합니다.

02

검사와 처리

services.py는 validators.py의 검사와 카테고리 조회 등을 거쳐 거래 객체를 만듭니다.

03

저장과 응답

repositories.py가 JSONL 파일에 기록하면 CLI가 저장 결과와 ID를 출력합니다. 처리 대상 오류는 데코레이터가 안내합니다.

명령마다 쓰는 파일과 검사 순서는 다릅니다. 위 도식은 실제 add 흐름의 대표 예시입니다.
